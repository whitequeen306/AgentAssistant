# 用户验证与商业测算方案

> 配套 `01-kaoyan-playbook.md`。本文件回答两个问题：
> **证据从哪来**（内测与对照实验设计）、**钱从哪来**（商业与市场测算）。
>
> 原则：所有数字必须**实测**，本文件给的是方法与模板，不是让你直接抄的答案。
> 表里的示例数字仅供排版参考，**成稿时必须替换成真实数据**。

## 一、为什么这两件事决定名次

上一轮评估里，"商业性与市场验证"只有 15 分、"材料与路演"10 分。

## 二、验证一：效率实验（择校调研耗时）

### 2.1 设计

| 项 | 内容 |
|---|---|
| 样本 | 60 人，随机分为实验组 / 对照组各 30 人 |
| 对象 | 2027 届考研学生（当前 9–10 月正是择校季，需求最强烈） |
| 任务 | "对比你目标专业的 4 所院校，输出初试科目、招生人数、参考书目、近三年分数线" |
| 实验组 | 使用 AgentAssistant（择校 Profile + 目录解析器） |
| 对照组 | 常规方式（研招网 + 搜索引擎 + 社交平台） |
| 完成标准 | 提交一份四要素齐全的对比表 |

### 2.2 指标

| 类型 | 指标 | 采集方式 |
|---|---|---|
| **主指标** | 任务完成耗时 | 系统日志自动计时（**不要靠自报**，会有偏差） |
| 主指标 | 关键字段准确率 | 人工核对 10 个字段，计算正确率 |
| 次指标 | 覆盖院校数 | 提交的对比表院校数量 |
| 次指标 | 认知负荷 | NASA-TLX 简版量表（6 题，2 分钟） |
| 次指标 | 净推荐值 NPS | 完成后 1 题 |

### 2.3 结果呈现模板

```
实验组（n=30）平均耗时  ___ 分钟，字段准确率 ___%
对照组（n=30）平均耗时  ___ 分钟，字段准确率 ___%
效率提升 ___ 倍（p < 0.05，独立样本 t 检验）
```

⚠️ **显著性检验必须做。** 评委里常有人懂统计，一句"p 值多少"就能让整页数据失效。
用 Python `scipy.stats.ttest_ind` 十几行代码的事。

### 2.4 需要在产品里补的（半天工作量）

一个**本地匿名埋点 + 用户授权开关**：
默认关闭，用户在设置里勾选"帮助改进产品"才上传耗时与功能使用次数，
**不采集任何文件内容、不采集身份信息**。
这既是数据需要，也是答辩时的加分项（隐私合规意识）。

## 三、验证二：效果实验（学习留存率）

这个实验**比效率实验更值钱**，因为它直接回答"你的产品到底有没有用"。

### 3.1 设计

| 项 | 内容 |
|---|---|
| 样本 | 40 人，随机分组各 20 人 |
| 材料 | 同一份专业课材料（建议选通用性强的，如某门公共课的一个章节） |
| 实验组 | 精读 → 练习室出题 → 判分 → Leitner 排期复习（7 天内有 2 次回炉） |
| 对照组 | 自主复习，不限方法，同样时长 |
| 测试 | 第 8 天，两组做同一套 15 题试卷（选择题 + 简答题） |

### 3.2 为什么这个设计站得住

- **有理论支撑**：间隔重复（Leitner / 遗忘曲线）是成熟的学习科学结论
- **可归因**：差异来自"是否按间隔复习"，机制清晰
- **产品数据可直接导出**：`practice/scheduler.py` 的 Leitner 五盒状态、
  `practice/store.py` 的答题记录，本就是结构化数据，**不需要额外开发**
- **可交叉验证**：把 Leitner 盒子分布与正确率做相关分析，
  能画出一条"复习轮次 → 正确率"曲线——**这张图放进 PPT 非常有说服力**

### 3.3 建议额外采集

- 每位被试的 Leitner 盒子迁移轨迹（1→2→3→4→5），可视化成桑基图或折线
- 错题类型分布（概念混淆 / 记忆缺失 / 理解偏差），由 `grader.py` 的解析产出

### 3.4 合规

知情同意书、可随时退出、数据本地存储、结果仅用于研究、不公开个人信息。
**建议找一位教育学/心理学的老师或学生做共同署名**——既补团队短板，又增加可信度。

## 四、验证三：内测运营数据（最基础，必须有）

| 指标 | 目标值 | 说明 |
|---|---|---|
| 累计激活用户 | ≥ 200 | 安装包下载 + 激活 |
| 周活跃（WAU） | ≥ 60 | 至少用一次核心功能 |
| 7 日留存 | ≥ 30% | 学生工具类产品的及格线 |
| 人均精读文件数 | ≥ 8 | 反映核心功能使用深度 |
| 练习室人均出题次数 | ≥ 4 | 反映闭环是否走通 |
| NPS | ≥ 30 | 口碑 |

**采集方式：本地埋点（用户授权）+ 内测群每周问卷。**

### 招募渠道（按效率排序）

1. 本校考研群 / 自习室 / 图书馆（**转化率最高，今天就能做**）
2. 目标院校的考研 QQ 群、小红书、知乎择校话题
3. 校内创新创业中心、教务处协助推广（挂了指导教师更容易）
4. 开源社区（GitHub / 少数派）——顺便补"开源影响力"

## 五、市场测算

### 5.1 三层市场

| 层级 | 口径 | 规模 |
|---|---|---|
| **TAM** | 全国有升学/专业课学习需求的大学生 | 2026 考研报名 343 万；全国普通本科在校生逾 2000 万 |
| **SAM** | 使用 Windows PC 学习、有明确备考需求、愿意为效率付费的学生 | 取 TAM 的 20%~30%，约 **70~100 万** |
| **SOM** | 3 年内可触达：100 所院校 × 院系级试点 + C 端付费 | 见下表 |

数据来源：教育部 2026 年考研报名人数 343 万（2023 峰值 474 万，三年累计减少 131 万）。

### 5.2 三年营收预测（示例，须替换为你的测算）

| | 第 1 年 | 第 2 年 | 第 3 年 |
|---|---|---|---|
| C 端付费用户 | 2,000 | 15,000 | 50,000 |
| C 端年费（学生价） | ¥49 | ¥49 | ¥49 |
| C 端收入 | ¥9.8 万 | ¥73.5 万 | ¥245 万 |
| B 端授权院系数 | 5 | 30 | 100 |
| B 端单价/年 | ¥15,000 | ¥18,000 | ¥20,000 |
| B 端收入 | ¥7.5 万 | ¥54 万 | ¥200 万 |
| **合计** | **¥17.3 万** | **¥127.5 万** | **¥445 万** |

### 5.3 成本结构（这是你的优势）

| 项 | 说明 |
|---|---|
| 服务器成本 | **近乎为零** —— 本地运行，无服务端 |
| 模型调用成本 | 按量计费或用户自带 Key，边际成本极低 |
| 主要成本 | 研发人力、院校渠道、内容运营 |
| 毛利率 | 显著高于 SaaS 类项目 |

**这句话要直接在答辩时说：** "我们是本地优先架构，每多一个用户几乎不增加成本，
这让我们可以用远低于在线服务的价格服务学生。"

### 5.4 商业模式建议（分阶段）

```
阶段一（校赛/省赛期）：免费 + 内测，换数据与口碑
阶段二（1 年内）  ：C 端增值（高级调研额度、跨设备同步、深度报告导出）
                    B 端试点（院系/实验室/图书馆授权）
阶段三（2~3 年）  ：院校数据服务（复试调剂信息更新、专业目录变更监控）
                    出版社/培训机构内容合作
```

⚠️ **不要讲"我们靠卖会员赚钱"** ——太单薄，评委会追问复购率。
推荐主线：**B 端授权打底 + C 端增值放量**，且 B 端有"引领教育"的政策buff。
