## 1. 战略判断：为什么考研是最佳切入点

### 1.1 市场足够大，且你能触达

| 年份 | 报名人数 | 变化 |
|---|---|---|
| 2023 | 474 万 | 历史峰值 |
| 2024 | 438 万 | −36 万 |
| 2025 | 388 万 | −50 万 |
| **2026** | **343 万** | **−45 万** |

数据来源：教育部（经中国网教育、新京报等公开报道引用）。2024 年硕士研究生招生 118.57 万人。

### 1.2 趋势正好站在你这边（这是关键）

不要只讲"考研人多"。今年的真趋势是 **"精准择考"**：

- 报名人数三连降，但**国家线"涨多降少"**——2026 年教育学 +6 分、图书情报 +8 分、哲学/历史学 +5 分
- 专家解读：留下来的考生"目标明确、备考充分"，**二战比例上升，竞争质量提高**
- 中国网教育原文：考生的决策逻辑正在从"品牌认知驱动"转向**"效果数据驱动"**
- 新东方《2027 中国大学生考研白皮书》已把"科学择校四步法"（学科实力 / 综合排名 / 专业特色 / 就业质量）列为标准方法

**翻译成你的路演语言：**
> 考研从"拼体力"进入"拼决策"的阶段。人数在降，但因为留下的人更理性，
> **信息搜集与判断能力反而成了决定性变量**。而这件事，恰好是 Agent 最擅长、人最不擅长的。

这个叙事比"AI 学习助手"高一个维度，而且**有官方数据背书，评反驳不了**。

### 1.3 你自己就是用户

`scratch/` 里的东西不是市场调研得来的，是你为了自己择校真实写出来的。
**这一点在路演上非常值钱**——"我们不是在想象需求，我们是在解决自己的问题，
然后把解决方案产品化"。评委对"假想痛点"极其敏感，对"真实痛点"极其宽容。

### 1.4 边界清晰，指标好量化

"择校调研耗时"是一个**能被秒表测量**的指标。这比"学习效率提升"这类虚指标强太多。

### 2.1 已有硬证据（直接可引用）

| 证据 | 数值 | 位置 |
|---|---|---|
| 抓取脚本 | 23 个 | `scratch/*.py` + `scratch/kaoyan-research/*.py` |
| 脚本代码量 | 1384 行 | 同上 |
| 中间产物文件 | 242 个 | `scratch/`（145）+ `scratch/kaoyan-research/`（97） |
| 抓取网页 | 109 个 HTML | 57 + 52 |
| 研招目录 PDF | 5 份 | `hit2026catalog.pdf`、`hrbeu2026catalog.pdf`、`hit2026_cankaoshumu.pdf`、`hit2026_qiangjun.pdf` 等 |
| 覆盖院校 | 5 个数据源 | 哈工大（本部 + 深圳）、哈工程、华东师大、东北大学、中国教育在线 |

### 2.2 三个"反常识"的技术细节（这是杀手锏）

这三条要在路演时**现场演示**，杀伤力远大于任何 PPT 文字：

1. **专业目录是异步加载的树形结构**，不是静态表格。
   证据：`scratch/kaoyan-research/ecnu_tree.json` —— 院系 → 专业 → 研究方向三层嵌套，
   必须模拟请求逐层展开才能拿到完整数据。

2. **PDF 里的科目代码是乱码编码**，无法复制粘贴。
   证据：`ecnu_subjects.txt` 中出现 `鈶?01-鎬濇兂鏀挎不鐞嗚\` 这类内容，
   实为"①101-思想政治理论"的 UTF-8/GBK 错编。学生只能手打。

3. **同一专业在不同院系的科目不同，必须交叉比对。**
   证据：华东师大 `160_085405`、`173_085405` 与 `162_085411` 的考试科目组合并不一致
   （如 408 计算机学科专业基础 vs 829 数据工程基础）。

**结论句（直接背下来）：**
> 这不是"搜一下就有"的信息。这是需要写脚本才能拿到的信息。
> 而我们写过了——然后我们把它做进了产品里。

### 2.3 需要补的一项：人工基线测量（半天）

光有脚本数据还不够，评委要的是"**人**做这件事要多久"。

做法：找 5 位不做计算机的同学，给他们同一个任务——
"对比哈工大、哈工程、华东师大、东北大学的计算机相关专硕初试科目和近三年分数线"，
**掐表记录**，并让他们自述卡在哪一步。

预期结果（写材料时保守表述）：

| 环节 | 预计耗时 |
|---|---|
| 找到各校研招网入口 | 20–40 min |
| 展开专业目录、下载 PDF | 40–60 min |
| 手工摘录并对齐字段 | 90–180 min |
| 搜索近三年分数线（多源） | 60–120 min |
| 汇总成可决策的表格 | 30–60 min |
| **合计** | **约 4–7.5 小时** |

⚠️ 这个数字**必须实测**，不能用估算值写进商业计划书。评委一问"数据怎么来的"就穿帮。

## 3. 资产②：考研垂直场景 Demo（2~3 周）

### 3.1 现有能力映射（不用重写，直接用）

| 考研需求 | 已有能力 | 对应模块 |
|---|---|---|
| 招生信息调研 | 多源搜索 + 交叉核验 + 带引用报告 | `subagents/runners/`（`dispatch_research`） |
| 保存研招页面、经验贴 | 浏览器扩展一键剪藏 | `browser-extension/` + `native-host/` |
| 专业课 PDF / 真题精读 | 右键精读 | `tools/file_tools.py` |
| 资料长期沉淀与问答 | 笔记 + 向量知识库混合检索 | `knowledge/` |
| 政治 / 英语 / 专业课自测 | 自动出题 + 本地判分 + 解析 | `practice/quizgen.py`、`grader.py` |
| 错题按遗忘曲线回炉 | Leitner 五盒调度（1/2/4/7/15 天） | `practice/scheduler.py` |
| 复试材料整理 | 文件归类、深度调研 | `subagents/…/organizer` |

**这套映射本身就是一张很好的 PPT 图**：左边一列考研真实任务，右边一列你已有的模块。

### 3.2 建议新增的三个增量（按性价比排序）

#### ★ 增量 A：择校调研 Profile（1~2 天，先做这个）

给 `dispatch_research` 增加一套「升学择校」输出模板，固定生成八列结构化对比：

```
院校层次 / 学科评估 / 招生人数（含推免占比）/ 初试科目代码 / 参考书目 /
近三年复试线 / 复试权重 / 就业去向
```

硬要求：**每一格必须带来源链接**，这是你对抗"AI 幻觉"的核心卖点。

产出：一份 Markdown 对比表 + 一张「一页纸择校决策卡」（可导出打印）。

#### ★★ 增量 B：研招目录解析器（3~5 天，这是真壁垒）

把 `scratch/` 里那 1384 行脚本产品化成一个工具：

- 输入：院校 + 年份（或用户剪藏的研招网页面）
- 处理：异步树逐层展开、编码修复、科目代码标准化、跨院系去重
- 输出：标准 JSON + 对比表

**为什么这是壁垒：** 这活儿必须踩过坑才知道怎么干（异步树、GBK 乱码、Cookie、
分页、每年改版）。通用大模型 + 通用爬虫干不了，做过的竞品也不多。
而且你**已经有 90% 的代码**。

#### ★ 增量 C：报名节点提醒（半天）

预报名 / 正式报名 / 确认 / 初试 / 出分 / 国家线 / 调剂系统开放——
挂到你已有的 `daemon` 定时任务上，做成本地提醒 + 自动触发调研更新
（"你关注的 3 所院校目录已更新，是否重新生成对比？")。

这个最便宜，但**最能体现"主动式 Agent"而非"问答机器人"**。

### 3.3 三分钟演示脚本（现场照着跑）

| 时间 | 动作 | 台词要点 |
|---|---|---|
| 0:00–0:35 | 现场打开华东师大研招网，点开树形目录；打开 `hit2026catalog.pdf` 展示乱码 | "这是学生每天面对的东西。注意这个科目代码，它没法复制。" |
| 0:35–0:50 | 一句话下达 | "帮我对比哈工大、哈工程、华东师大、东北大学计算机相关专硕，重点看初试科目和近三年分数线。" |
| 0:50–1:50 | 调研卡片实时滚动（多轮搜索 → 交叉核验） | "它在交叉核验，不是一次性生成。每个结论都能点开看来源。" |
| 1:50–2:20 | 生成八列对比表 + 一页纸决策卡，一键存入学习库 | "从四小时到四分钟。" |
| 2:20–2:50 | 选一份参考书目 PDF → 练习室自动出题 → 故意答错一题 | "考完不是结束。" |
| 2:50–3:00 | 展示该题进入 Leitner 盒子、到期提醒 | "两天后，它会把这道题推回来。**这才是学习。**" |

⚠️ 演练要求：全流程本地预跑 5 遍以上，并**准备一份录屏**。
网络抖动导致现场翻车是这类项目最常见的失分原因。

## 4. 资产③：路演开场故事（1 天）

### 4.1 60 秒开场口播稿（可直接背）

> 去年九月，我要考研。
>
> 我需要对比四所学校、三个专业的招生目录。听起来很简单，对吧？
>
> 我打开第一所学校的研究生院网站——专业目录是一棵异步加载的树，要一层一层点开。
> 我下载了第二所学校的 PDF——里面的考试科目是乱码，一个字都复制不出来。
> 第三所学校，同一个专业代码，放在不同学院，考试科目居然不一样。
>
> 那天我放弃了手动整理，写了第一个爬虫脚本。
>
> 后来我又写了二十二个。一共一千三百行代码，二百四十二个中间文件。
>
> 我做的是计算机专业。**那些不学编程的同学呢？**
> 他们只能花一整个星期，手动复制粘贴，然后在每年九月目录更新的时候，再来一遍。
>
> 考研报名人数今年是三百四十三万，比三年前少了一百三十万。
> 但国家线反而涨了——教育学涨了六分。
> 留在考场上的人更理性了，**考研从拼体力变成了拼决策**。
>
> 而决策所需要的这件事——从混乱的源头里拿到准确信息、交叉验证、变成可执行的判断——
> 恰好是 AI 最擅长、人最不擅长的。
>
> 所以我没有停在爬虫脚本。我把这一整套能力，做进了 AgentAssistant。

### 4.2 这段稿子为什么有效

| 技巧 | 体现 |
|---|---|
| 具体数字 | 22 个脚本、1384 行、242 个文件、343 万、6 分 |
| 有画面 | 乱码 PDF、点不开的树、复制不出来的科目 |
| 有转折 | "我做的是计算机专业，那些不学编程的同学呢？" |
| 有数据背书 | 引用教育部报名人数与国家线 |
| 有逻辑闭环 | 个人痛点 → 群体痛点 → 市场趋势 → 产品必然性 |

## 5. 验证方案（与 Demo 并行，3~4 周）

详见 `02-validation-plan.md`。核心是三个数字：

1. **效率**：择校调研耗时（目标：4–7.5 h → ≤1 h）
2. **效果**：7 天后知识点回忆正确率（用练习室 Leitner 数据做 A/B）
3. **留存**：7 日 / 30 日留存、人均精读文件数、练习室使用频次

## 6. 评委必问与标准答法

**Q1：考研人数连续三年下降，你的市场在萎缩，怎么办？**
三層回应：① 343 万仍是巨大基数，且需求从"量"转向"质"，单客价值上升；
② 国家线不降反升说明竞争强度未减，信息服务的刚需性反而增强；
③ 考研只是首个切入点，同一套能力可迁移到保研、考公、留学、期末备考、科研入门。

**Q2：研招网是官方免费渠道，你有什么价值？**
研招网提供的是**原始数据**，不是**决策**。它不会把五所学校对齐成一张表，
不会告诉你"以你的背景冲这个专业风险多大"，也不会在报名前一周提醒你科目变了。
我们做的是"数据 → 决策"的那一层。

**Q3：抓取研招网合规吗？**
产品形态是**解析用户自己打开的页面**（浏览器扩展剪藏 + 本地解析），
只读取公开信息、低频访问、不绕过鉴权、不采集任何个人身份信息。
这一点要**主动写进商业计划书的合规章节**，不要等评委问。

**Q4：AI 生成的招生信息错了怎么办？学生报错名你负责吗？**
这是必问题。答法：① 每个字段带来源链接，可一键回溯原文；
② 关键字段（科目代码、招生人数）做双源交叉核验，冲突时**标红提示人工确认**而非静默生成；
③ 产品定位是**决策辅助**，最终以官方公布为准，界面上有明确免责提示。
——建议把"冲突标红"这个设计真的做出来，一句话能顶三页 PPT。
